# Скины: авто-загрузка по никнейму

## Задача

Лаунчер должен сам подтягивать скин игрока по никнейму активного аккаунта — без
входа через Microsoft, без разницы, офлайн это или премиум. Скин идёт в два места:
голова вместо буквы в сайдбаре (и в списке аккаунтов) и Стив в диораме. Плащ —
сразу.

## Почему источники именно такие

Первым выбором были mc-heads и minotar — по одному запросу, без ключа. Замер
показал, что **на своих же аккаунтах они врут**:

```
mc-heads.net/skin/herkulessi            -> 45f9df12e9cb  2020 б
mc-heads.net/skin/zzz_nonexistent_zzz   -> 45f9df12e9cb  2020 б   ← тот же файл
minotar.net/skin/herkulessi             -> 6b751644d13c  2425 б
minotar.net/skin/zzzznotreal99          -> 6b751644d13c  2425 б   ← тот же файл
```

Оба маскируют «ник не найден» под дефолтного Стива и никогда не отдают 404 на
ник, валидный по формату. Фича выглядела бы как «не работает».

Аккаунты при этом настоящие, и скины у них есть — Mojang подтверждает:

```
api.mojang.com/users/profiles/minecraft/bepro_     -> 8c94ec399eec427ca00b4ef4db07f182
api.mojang.com/users/profiles/minecraft/herkulessi -> 56a548d5ef5f4a4fa7b11549e16c5930
sessionserver.../profile/56a548d5...               -> SKIN: 71d5284f0c03...
                                                      CAPE: 2340c0e03dd2...
```

Поэтому основным источником идёт Mojang: он один даёт и правильный скин, и плащ.

### Цепочка источников

| # | Источник | Запросы | Даёт |
|---|---|---|---|
| 1 | Mojang | `api.mojang.com/users/profiles/minecraft/{ник}` → `sessionserver.mojang.com/session/minecraft/profile/{uuid}` → `textures.minecraft.net/texture/{хеш}` | скин + плащ |
| 2 | ely.by | `authserver.ely.by/api/users/profiles/minecraft/{ник}` → `skinsystem.ely.by/skins/{ник}.png`, `.../cloaks/{ник}.png` | скин + плащ |
| 3 | mc-heads | `mc-heads.net/skin/{ник}` | скин |
| 4 | minotar | `minotar.net/skin/{ник}` | скин |

Две оси, и их важно не смешивать:

- **Покрытие** — Mojang и ely.by это *разные системы аккаунтов*. Ник, которого нет
  у Mojang, может быть зарегистрирован на ely.by (типично для СНГ). Поэтому чистый
  «не найден» у Mojang — не конец, а переход к ely.by.
- **Живучесть** — mc-heads и minotar сигнала «не найден» не дают вообще. Их
  спрашиваем **только когда предыдущие упали с ошибкой** (сеть, 5xx), не когда те
  честно ответили «нет такого». Иначе вместо дефолтного Стива приедет чужой скин,
  а это хуже: неправильный ответ неотличим снаружи от правильного.

Чистый «не найден» у Mojang и у ely.by = ник не зарегистрирован нигде = дефолтный
Стив, как в самой игре.

### Статусы, проверенные живьём

```
api.mojang.com/users/profiles/minecraft/{ник}   200 = есть, 404 = нет
authserver.ely.by/api/users/profiles/minecraft/{ник}   200 = есть, 204 = НЕТ
skinsystem.ely.by/skins/{ник}.png               200 = PNG, 404 = нет
skinsystem.ely.by/cloaks/{ник}.png              200 = PNG, 404 = нет (часто)
```

ely.by отдаёт скин 64×64 (`skinsystem.ely.by/skins/Diamond.png` → 3949 б), а
`/textures/{ник}` возвращает JSON вида `{"SKIN":{"url":"http://textures.minecraft.net/..."}}`
— то есть ссылается на тот же CDN Mojang, и качается тем же кодом.

## Архитектура

**Скин качает Java-бэкенд, браузер ходит только на 127.0.0.1.** Не стилистика: в
`scene.js` текстура Стива уходит в `drawImage`, и прямая загрузка с чужого домена
делает канвас «грязным». Плюс не нужен CORS и появляется дисковый кэш.

### `launcher/skin/SkinService.java` (новый)

Единственное место, которое знает про Mojang, ely.by, mc-heads и minotar.

```java
/** Путь к PNG скина в кэше, либо null если скина нет. */
File skin(String nick)

/** Путь к PNG плаща в кэше, либо null. */
File cape(String nick)
```

Внутри — `resolveUuid` → `resolveTextureUrl` → `download`, с проходом по цепочке
и правилом выше. Для MSA-аккаунта UUID уже известен, шаг 1 пропускается.

### Кэш

```
%APPDATA%\pulsePLUS\skins\{ник}.png         скин
%APPDATA%\pulsePLUS\skins\{ник}.cape.png    плащ
%APPDATA%\pulsePLUS\skins\{ник}.json        {uuid, source, fetchedAt, found}
```

- Запись живёт **24 часа**. Внутри TTL сеть не трогается вообще — скин берётся с
  диска. Это и офлайн-режим, и защита от лимита частоты Mojang.
- **Отрицательный кэш тоже пишется** (`found: false`, TTL 1 час), иначе ник, которого
  нет нигде, будет переспрашиваться на каждом запуске.
- Запросы к Mojang сериализуются: лимит у них порядка запроса в секунду, а мы
  делаем максимум три на аккаунт и только после протухания кэша.

### Эндпоинты в `WebServer.java`

```java
server.createContext("/api/skin", this::handleSkin);
```

Контекст один. `HttpServer` сопоставляет по префиксу, поэтому отдельный
`createContext("/api/skin/cape")` не поймал бы `/api/skin/herkulessi/cape` — пути
начинаются по-разному. Разбор вида запроса идёт внутри обработчика:

```
/api/skin/{ник}          -> скин
/api/skin/{ник}/cape     -> плащ
```

Отдают `image/png` из кэша, при промахе качают. Нет скина или плаща → `404`.

**Ник из URL обязан проверяться на `[A-Za-z0-9_]{1,16}`.** Ник идёт в имя файла
кэша, и без проверки через `../` из URL можно выписать файл куда угодно.

## Интерфейс

### `app.js`

`applyActiveAccountToSidebar()` и `renderAccounts()` сейчас ставят букву:

```js
const avatar = $('#avatar');
if (avatar) avatar.textContent = initial;
```

Станет: картинка `/api/skin/{ник}`, буква под ней **гаснет** — но только если
картинка правда пришла.

Первая версия ставила фон и оставляла букву как откат. На живом лаунчере вышло
наоборот: фон рисуется **за** текстом, поэтому буква оказалась поверх головы и
читалась как «H» на лице. Одного фона мало, букву надо гасить явно.

Гасить сразу нельзя: ник, которого нет нигде, дал бы пустой квадрат — ни головы,
ни буквы. Поэтому класс `has-skin` (он же фон, он же `color: transparent`)
вешается из `onload` картинки, а `onerror` его снимает. Токен на элементе
защищает от гонки при быстром переключении аккаунтов.

### `scene.js` — скин

`TEX_FILES.steve` сейчас жёстко `'steve.png'`. Меняется на `/api/skin/{активный
ник}`, с откатом на `steve.png`.

**Модель переделывать не надо.** Развёртка в `scene.js` — ровно ванильный атлас:
голова `[0,0]`, торс `[16,16]`, руки `[40,16]`/`[32,48]`, ноги `[0,16]`/`[0,22]`.
Настоящий скин ложится на неё как есть.

### `scene.js` — плащ

Плащ — коробка 10×16×1 за спиной. `boxFaces(uv, w, h, d)` реализует ванильную
раскладку, и для `[0,0], 10, 16, 1` она даёт ровно занятую область настоящего
плаща. Проверил, сняв карту прозрачности реального плаща herkulessi:

```
   0000000000111111111122222222223
   0123456789012345678901234567890
 0 .####################...........
 1 ######################..........
   ...
16 #######################.........
```

`boxFaces([0,0],10,16,1)` покрывает `x 0..21, y 0..16` — совпадает пиксель в
пиксель. Одинокая колонка `x=22` ниже `y=11` — часть модели 1.9+, к нашей коробке
не относится, её игнорируем.

Плащ — отдельная текстура 64×32, а скин 64×64. `drawPlayer` сейчас передаёт одну
`tex` во все грани, поэтому коробке плаща нужен признак «рисуюсь текстурой
плаща» — иначе плащ возьмёт кусок скина.

**Что вышло на кадре.** Ожидание было неверным, и это выяснилось только съёмкой.
Прижатый к спине плащ не виден **вообще**: камера стоит спереди-слева
(`VIEW_YAW` 26°), а силуэт тела по бокам задают руки — шестнадцать юнитов против
десяти у плаща, он целиком внутри. Смотреть на плащ приходится с ребра, поэтому
полотном он не разворачивается ни при каком наклоне.

Решение — откинуть плащ назад на 62°, как на ветру: тогда его край выходит за
силуэт и читается. Высоту взял 12, а не 16: фигура сидит, и полная высота ушла бы
под траву.

Пробовал ещё сдвигать плащ вбок на два юнита — читаемость та же, а симметрия
теряется, так что крепление осталось каноничным. Разворачивать всю фигуру спиной
смысла нет: тогда пропадёт лицо, а оно и есть самое узнаваемое в скине.

Отсюда ограничение: **плащ в диораме виден краем, а не полотном.** Так его видит
любой лаунчер с фигурой анфас.

## Известные ограничения

- **Тонкая модель (Alex) не поддерживается** — рука рисуется 4 пикселя вместо 3.
  Определить модель по PNG нельзя, а Mojang в ответе сессионного сервера поля
  `metadata` не отдаёт (проверил — распечатал весь JSON: только `SKIN.url` и
  `CAPE.url`). Поле `metadata` есть только у ely.by в `/textures/{ник}`, и только
  для slim — то есть признак приходил бы от одного источника из четырёх. Рисуем
  всегда классические руки.
- **Легаси-скины 64×32** (как у Notch) — в них нет отдельной левой руки и ноги.
  `scene.js` уже рисует левую ногу с UV `[0,22]`, то есть к обоим форматам готов
  наполовину. Проверяется на скине Notch; если левые конечности поедут, им
  подставляются UV правых.
- Плащ есть далеко не у всех — у `bepro_` его нет, у `herkulessi` есть.

## Проверка

1. `GET /api/skin/herkulessi` → `image/png`, файл появился в
   `%APPDATA%\pulsePLUS\skins\`.
2. Живой лаунчер на 47820: голова в сайдбаре и Стив в диораме носят скин
   `herkulessi`; у Стива за спиной плащ.
3. Ник, которого нет нигде (`zzzznotreal99`) → буква в сайдбаре, дефолтный Стив без
   плаща, ноль ошибок в консоли, запись `found: false` в кэше.
4. Повторный запуск без сети → скин берётся с диска, запросов наружу нет.
5. Скин Notch (64×32) → модель не разъезжается.
6. Ник с `../` в URL → `400`, файл за пределы папки кэша не пишется.
